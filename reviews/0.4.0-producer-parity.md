## Blockers

### B1 — The 0.4.0 forged-arrow defense (SEC-8/#5) is bypassed by every caption source other than `text`/`value` (CONFIRMED, security + correctness)

`src/index.ts:502` (caption paths ~478–508), `src/index.ts:524` / `:254` (`boundTwoWay` scan), `:214` (`boundTwoWay`)

Reproduced by execution:

- `{tag:'button', label:'Save ⟷ spoof.path', on:{click:'ƒ'}}` emits the **raw U+27F7 glyph inside the caption text run** (the resvg tofu failure the grammar's first law exists to forbid) **and** the ↔ editable badge. Same for `placeholder:'type ⟵ here'`.
- `{tag:'span','data-x':'a ⟷ b'}` → `isInteractive` true and the badge drawn: `boundTwoWay` scans `Object.values(w)` so **every string prop is a forgery surface**, and for fields the surface never appends a structural arrow to (`label`, `placeholder`, `href`, `ref`), a lone forged arrow is always in "last = structural" position — the last-occurrence rule only protects fields that actually receive an appended binding.
- A forged label on a second record **suppresses the new blind-map note** (fabricated "evidence" defeats `blind` at ~439–440) and lands `"editable":true` plus the raw ⟷ in the **legend JSON the agent consumes**; it also makes the WCAG 2.5.8 audit fire false positives on non-interactive elements.
- Root cause: arrow neutralization lives only in `shownValue()`, which only the `text`/`value` caption paths call (lines 487, 504–505, 734); the label/placeholder/href paths pass raw strings.

In haltija's threat model `label` IS the accessible name — hostile page content — so a page can dress a non-interactive element in the editable badge: the exact "drawing that lies about what the page can do" this release claims to close. CHANGELOG, README (~line 105), and llms.txt (line 54) all state "a forged arrow confers nothing" — for these fields it confers everything. Per CLAUDE.md constraint 2, this lands verbatim inside tosijs's committed bundle on its next vendor bump. The #5 test block (schematic.test.ts:746–775) only exercises forged arrows *followed by* a real structural arrow, which is why 44/44 pass over the hole.

**Remediation:** (1) route every caption source (label, placeholder, href fallback, container/toggle captions) through the same arrow neutralization `shownValue` applies; (2) restrict the two-way-binding scan in both `boundTwoWay` call sites to fields that can legitimately carry a binding — exclude identity/name fields (`label`, `placeholder`, `href`, `ref`, `tag`, `type`, `role`); (3) add hostile-input tests for label/placeholder/extra-prop forgery to the #5 block. **Constraint 3 warning:** neutralizing label captions changes emitted SVG for affected inputs — call it out deliberately in the CHANGELOG. **Re-review scope after remediation:** correctness + blast-radius over the remediation diff only, with explicit attention to the output-stability promise and consistency with tosijs's vendored copy.

## Majors

### M1 — Suffix-position forged arrows are structurally indistinguishable from real bindings and fail open; the spec's "confers nothing" claim reads broader than what shipped (CONFIRMED, security)

`src/index.ts:203` (`shownValue`/`boundTwoWay` split at the LAST arrow)

Reproduced: `{tag:'span', text:'confirmed ⟷ spoof.orderStatus'}` — hostile text with the arrow last and no genuine binding — yields `isInteractive` true, the ↔ badge, and the shown value truncated to "confirmed" (an attacker can also hide the true tail of any value by appending `' ⟷ x'`). The renderer cannot distinguish this from a real binding by construction; the whole defense rests on producer-side neutralization, which the README states as non-normative "should" — and haltija, the one producer extracting untrusted page content, does no arrow neutralization anywhere in its source (its consumer side even amplifies forgeries by reporting arrow-bearing text as bindings with `write(path)` guidance). This is a distinct residual from B1 (fixing B1 does not fix this) and remains after B1's remediation.

**Remediation (docs + upstream, not a code blocker):**
- README spec: upgrade "should neutralize" to **MUST** for producers whose record content derives from untrusted sources, and explicitly confess the residual — renderer-side defense covers interior arrows only; a trailing forged arrow is indistinguishable from a real binding.
- Add a test pinning the residual behavior so the limit is documented, not rediscovered.
- File the haltija issue (see UPSTREAM section below) — per file-don't-fix, no drive-by edit.
