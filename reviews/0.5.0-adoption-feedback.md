## Gate (blocker)

### G1 — The `redacted` legend gate is fail-open: `secret:true` records whose facts were NOT actually withheld republish them verbatim, with `redacted:true` affirmed alongside the leak (CONFIRMED, security, major promoted to gate) — `src/index.ts:858`

Verified empirically: `schematic({wiring:[{tag:'a', secret:true, href:'https://app.example/magic?token=SECRET123', on:{click:'ƒ'}, bounds:…}]})` produces a legend entry containing the full token URL **and** `redacted:true`, and draws the truncated URL as the caption. The caption chain falls back to `w.href` with no secret check; the legend pushes `elided.href` unconditionally; line 858 stamps `redacted:true` purely from the flag, never verifying withholding. `secret` exists precisely for magic-link tokens, so the upstream failure this must guard against is "producer marked it secret but a bug left the href in" — and the renderer then ships the credential inside an artifact whose legend affirmatively asserts it was withheld. The existing test only exercises a well-behaved producer (its secret record carries no href), so the fail-open path is untested.

**Why this gates the tag rather than riding as a follow-up:** `severityUncertain` points upward; the verifier confirmed the mechanism and only withheld blocker status because a correct producer never hits it — but the field's semantics ship in 0.5.0, and scrubbing later changes output for unchanged input (constraint 3: semver-minor-at-least, deliberate, not drift). This matches the 0.4.0 round-2 precedent: an unresolved confirmed finding in the multi-producer contract meets the gate criterion.

**Remediation:** when `w.secret === true`, scrub withholdable facts before drawing and legend-building (drop `href`/`value`; exclude `label`/`text`/`value`/`href` from the caption chain so the `[withheld]` path always fires), so `redacted:true` can never co-occur with the facts it claims were withheld. This touches record-format semantics (constraint 4): land via an issue with tosijs sign-off, but make the decision **before** tagging. Add the hostile test: `secret:true` with `href`/`label`/`value` present. **Re-review scope: correctness + blast-radius over the remediation diff only.**

### Fold into the same remediation diff (confirmed; would otherwise be fix-now follow-ups)

- **R1 (CONFIRMED, security + correctness, minor — deduped across 2 lenses)** — the `[withheld]` caption is built AFTER the `neutralizeArrows` choke point, so an arrow token forged into `w.tag` rides a caption run raw. `src/index.ts:621`. Verified: `{tag:'a ⟷ fake', secret:true, text:'⟵ s.name', …}` emits raw U+27F7 inside a caption `<text>` run — the exact class grammar law 1 forbids and the class 0.4.0's B1 blocked on; line 621 sits directly under the comment claiming every caption source is neutralized at one choke point. Narrow reach (secret + empty caption chain + arrow-bearing tag), no XML injection. One-line fix: wrap the fallback in `neutralizeArrows(...)` (or move the assignment above line 617); pin with an arrow-in-tag test. Since G1's scrub makes the `[withheld]` path fire more often, fix R1 in the same diff or G1 widens R1's reach.
- **R2 (CONFIRMED, security + correctness, minor — deduped across 2 lenses)** — the #12 flags hardening stops three lines short: `flags:[null]` throws at `first.label` (`src/index.ts:722`) and `flags:[{kind:'x', label:42}]` throws `s.replaceAll is not a function` in `neutralizeArrows` (`src/index.ts:732`) — verified; one malformed producer flag kills the entire render, and the CHANGELOG's "a flags entry without kind no longer throws" overstates coverage (literally true, adjacent code still crashes). Guard as the forEach was guarded: `typeof first?.label === 'string' && first.label !== ''`, `flagColor(first?.severity)`; add hostile tests for `flags:[null]` and a non-string label alongside the existing #12 test.
