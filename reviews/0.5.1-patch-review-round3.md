## Findings (deduplicated, grouped by severity)

### Minor
1. **[correctness + security, CONFIRMED] The CHANGELOG says "no verdict changes", but `schematic()`'s `undersized` verdict changes for the same input** (`CHANGELOG.md:31-35`)
   - Reproduced side by side on a 30x30 button with `on.click` and `targetSize: '44'`:
     - **0.5.0:** coerces `'44'`, so the legend shows `undersized: '30×30 — below 44×44 (WCAG 2.5.8)'` and the amber bar is drawn.
     - **HEAD:** `finiteOr` falls back to 24, so there is no undersized entry and no bar.
   - For callers passing config-file or query-string values, the audit now fails open.
   - **Related gap, not lens-verified but probed by the completeness pass:**
     - `targetSize: null` used to mean "off" (`w < null` is false). It now becomes 24, so a 10x10 button gains `undersized: '10×10 — below 24×24'` and a bar.
     - Null `pad`, `fontSize`, `minLabelHeight` and `maxCaption` used to coerce to 0 and now use their defaults, so the SVG changes.
     - Records with numeric-string bounds (e.g. `'10'`) are no longer drawn, so their verdicts disappear too.
   - `isInteractive` and `targetSizeFinding` themselves really are unchanged. The wrong part is the claim about what the renderer reports.
   - **Fix now (Tier 0, doc only):**
     - Keep the fail-closed behaviour; the option tests pin it.
     - Remove or qualify "no verdict changes".
     - Add a separate **"Verdict changes"** section, as constraint 3 and issue #14 require (format as in the 0.4.0 `href` section). It should name: non-number `targetSize` (numeric strings such as `'44'`/`'0'`, and `null`) now uses 24; null numeric options now use their defaults instead of coercing to 0; records with non-finite or string bounds are no longer drawn or flagged.
   - **Re-review scope:** Tier 0 plus dx/docs over the CHANGELOG diff. If you decide instead to make `targetSize` fail toward strictness, run correctness over that remediation diff.
2. **[blast-radius] (unverified) The security fix reaches tosijs only when tosijs re-vendors**
   - `../tosijs/src/schematic.ts` has no `finiteBounds`/`finiteOr`, and `tosijs/UPSTREAM.md` has no entry for #2739.
   - Until tosijs runs `bun update` and rebuilds, its consumers keep the injectable renderer.
   - No code change is needed in this repo. File upstream (see below).

### Nit
3. **[correctness + security] (unverified) "Finite inputs" does not mean finite output** (`src/index.ts:539`)
   - `pad: 1e308`, or `bounds {x:1.7e308, width:1.7e308}`, emits `viewBox="… Infinity Infinity"` and `width="Infinity"`.
   - This is not an injection: a stringified number can contain only digits, `.`, `e`, `+`, `-`, `Infinity` or `NaN`. The output is still unrenderable SVG, and it contradicts the no-NaN/Infinity invariant that the `within` test asserts.
   - **For this release:** reword the CHANGELOG/README claim to "derives from finite inputs; no attribute can contain anything but a JS number's text".
   - **Later:** add a final `Number.isFinite` check on the viewBox extents that returns the empty map, plus a test for it.
