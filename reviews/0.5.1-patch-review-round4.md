## Confirmed majors (adversarially verified, gating the tag)

### M1. Comparison-only options reject `Infinity`, so bytes and the legend change for valid 0.5.0 config (security + blast-radius, confirmed)

`src/index.ts:400-404` `optionNumber` falls back whenever `!Number.isFinite(Number(value))`.

- **`maxCaption: Infinity`** ("never truncate") becomes 36. In 0.5.0 the full caption drew; now it is truncated or wrapped differently, and the `legend` entry count changes.
- **`minLabelHeight: Infinity`** ("legend only") becomes 14. In 0.5.0 every record went to the legend; now captions draw in the box. The legend count goes from N to fewer.

In 0.5.0, neither value ever reached an attribute. They feed only `slice`, `Math.min(…, finite)` and the height comparisons (src/index.ts ~702, 778, 844-856), and 0.5.0's SVG for them was clean. So the security fix did not need to reject them. The CHANGELOG (lines ~24-26) says "every option value that drew correctly in 0.5.0 draws byte-identically, which `bun run stability` now pins". That is false here. OPTION_CASES (`tools/byte-stability.ts:122-130`) has no Infinity case, and `src/schematic.test.ts:1199-1214` (`hostile.Infinity` → baseline) pins the regression as expected behaviour. Under CLAUDE.md constraint 3, this is unlicensed drift in a patch release that tosijs re-vendors and commits.

### M2. `targetSize: ±Infinity` changes the `undersized` verdict, and the CHANGELOG does not say so (security, confirmed)

- `targetSize: Infinity`: in 0.5.0 every interactive record was flagged ("below Infinity×Infinity"). At HEAD only records under 24 px are flagged.
- `targetSize: -Infinity`: in 0.5.0 the audit was **off** (`<= 0`). At HEAD it falls back to 24, so the audit turns **on**.

The "Verdict changes" section (CHANGELOG.md ~37-49) says "only input that broke its declared types is affected", but ±Infinity is a valid `number`. Constraint 3 and issue #14 require every case where the same input gets a different verdict to be named.

**Remediation for M1 + M2. Pick one route and state it in the commit:**
- **(preferred, code)** Split coercion by sink. For options that only feed comparisons or bounded arithmetic (`maxCaption`, `minLabelHeight`, `targetSize`), reject only NaN and let ±Infinity through. That restores 0.5.0 bytes and verdicts. Options that print (`pad`, `fontSize`, `within` fields) stay finite-only. Update the `hostile.Infinity` expectation in the options test loop for those three options. Add `Infinity` and `-Infinity` cases for `maxCaption`, `minLabelHeight` and `targetSize` to OPTION_CASES and to the round-3 verdict test.
- **(docs only)** Keep the code. Reword the byte-identity claim, and list ±Infinity (maxCaption, minLabelHeight, targetSize) under "Verdict changes" and as a deliberate output change. Note that this is a constraint-3 semver-minor-class change shipping in a patch.

**Re-review scope:** correctness + blast-radius over the remediation diff only. Tier 0 alone is enough if the docs route is taken.

## Confirmed minor (folded into the gates)

### m1. `fontSize: null` / `''` / `false` now emit `font-size="0"`, so all text is invisible (correctness + blast-radius, confirmed, adjusted to minor)

`Number(null)` is 0, so `font-size="0"` appears on every caption, ref and ↔ badge, with no error (`true` gives `"1"`). 0.5.0 emitted `font-size="null"`/`""`, which renderers ignore, so text stayed visible. It was mispositioned, though: 0.5.0's layout math already used 0. The value breaks the declared type and 0.5.0 did not draw it correctly, so the CHANGELOG promise is not literally broken. Still, the README/CHANGELOG line "`null` is 0" leads a reader to expect "unset", and the result goes from visible to silently empty. OPTION_CASES never pins fontSize.

**Remediation (Gate 2):** treat `null`, `''`, booleans and any coerced value ≤ 0 as unset for `fontSize`, so it falls back to 11. `targetSize` must keep null as off. Alternatively, keep 0 and say in the CHANGELOG that fontSize null/''/false now renders invisible text. Either way, add a unit assertion.
