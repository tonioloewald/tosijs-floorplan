## Confirmed findings (fix before tag; doc-only, Tier 0 re-review)

**C1 (minor, confirmed; correctness and security lenses agree, deduped). The Verdict-changes section says "no option changes any verdict", but a `within` with a wrong-type field now erases `undersized` verdicts.**
- File: `CHANGELOG.md` around lines 43-49.
- Input: one 18x18 `on`-bearing button, with `within: {x:'0', y:0, width:300, height:300}` (or `width:'300'`).
- 0.5.0 legend: `[{index:0, tag:'button', caption:'x', undersized:'18×18 — below 24×24 (WCAG 2.5.8)'}]`.
- HEAD legend: `[]`, with `viewBox="0 0 0 0"`.
- Cause: when `withinOk` is false, `src/index.ts` around lines 494-503 filters out every record.
- Why it matters: the audit passes silently, with no note to tell it apart from an empty region. Constraint 3 / #14 requires this to be named in the Verdict section, which tosijs reads.
- Fix: add a Verdict-changes bullet. It should say that a `within` with any x/y/width/height that is not a number primitive (numeric string, boolean, array, object, Number wrapper) draws nothing, so the records under it lose their legend entries, including `undersized`. Qualify the sentence to "no option *of the declared type* changes any verdict".
- In the same bullet: a string `fontSize` ('12') used to feed `cramped` as 36 and now uses 11, which changes what moves into the legend. That change also belongs here (completeness gap; verify, then list it).
- If board #2744 (within note) is the planned way to make a rejected `within` visible, cite it from the bullet.

**C2 (minor, confirmed; blast-radius). The security fix will not reach tosijs through `bun update`.**
- `../tosijs/package.json:90` pins `"tosijs-floorplan": "0.5.0"` exactly.
- `vendorSchematic()` in `../tosijs/bin/site.ts` compares against the *installed* copy and returns early on a match.
- `../tosijs/src/schematic.ts` has 0 occurrences of `finiteBounds`.
- Fix: reword CHANGELOG ~line 41 to "tosijs picks the fix up when it bumps its pinned version and re-vendors". Correct CLAUDE.md constraint 2's "next `bun update` + rebuild" the same way. File the upstream ask as a pin bump (see UPSTREAM section).
