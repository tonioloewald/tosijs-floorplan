## Blockers (must fix before tagging)

### B1 [security, blocker, VERIFIED]: `secret` redaction fails open for non-primitive truthy values
- **Where:** `src/index.ts:288-290`. `readRecord` sends `secret` through `scalar()`, which maps objects, functions and symbols to `undefined`. The gate at about line 744 is `Boolean(w.secret)`, so it returns false for these markers.
- **Repro:** `schematic({wiring:[{tag:'a', secret:X, href:'/magic?token=X', label:'leak', on:{click:'f'}, image:'data:...', bounds}]})` with X set to `{}`, `[]`, `new Boolean(true)` or `()=>1`.
  - HEAD draws the label and the `<image>`, and the legend carries `href:'/magic?token=X'`.
  - v0.5.1 gives `redacted:true` and no label, image or href.
- **Contract broken:** README:93 and CHANGELOG:191 both say "any truthy `secret` scrubs (malformed errs toward withholding)".
- **Fix:** give `secret` its own STRUCTURED reader that fails closed. For example: `v => (v !== null && (typeof v === 'object' || typeof v === 'function' || typeof v === 'symbol')) ? true : v`. This matches 0.5.1's `Boolean()` for every type.
- **Tests:**
  - When `secret` is the hostile field in the fuzz `check()`, assert that redaction holds: no label and no `<image` in the SVG, and no href in the legend.
  - Add explicit tests for `{}`, `[]`, `new Boolean(false)` and a function.
- **Re-review scope:** correctness and security over the `readRecord` change and its tests.

### B2 [correctness, major, VERIFIED; deduped with the security lens minor]: legend `flags` are no longer verbatim
- **Where:** `src/index.ts:270-274`. `STRUCTURED.flags` rebuilds each flag as `plainOf(f, ['kind','label','severity'])`, and line 1030 (`elided.flags = w.flags`) publishes that trimmed copy.
- **Repro:** a cramped button with `flags:[{kind:'contrast',label:'2:1',severity:'warn',ratio:2.1}]`.
  - 0.5.1 legend flag: `{kind,label,severity,ratio}`. HEAD drops `ratio`. This is plain JSON input, so it is an output change under constraint 3.
  - With `flags:[{kind,label}]`, which is the declared type, HEAD adds an own `severity: undefined` key. `in` checks and toStrictEqual change; JSON output does not.
- **Contract broken:** README:113-115 says flags are "verbatim, deliberately … copied as the producer computed them". The CHANGELOG says "no input of the declared type changes".
- **Why the guard missed it:** `bun run stability` passes because its fixtures carry only `kind`, `label` and `severity`, the flagged fixture is not cramped, and the judge compares `JSON.stringify` output.
- **Fix:** snapshot every own enumerable key of each flag through `scalar()`, and copy `severity` only when the source has it.
- **Tests:** add a stability case with a cramped flagged record whose flag carries an extra field. Add an absent-severity case that is judged structurally, not through JSON.
- **Re-review scope:** correctness and blast-radius over the remediation diff.
