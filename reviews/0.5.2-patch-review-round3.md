## Findings

### Minor

**M1 [correctness + security, CONFIRMED, deduped]: `targetSizeFinding({ ...w, bounds: geometry.get(w) }, ...)` drops inherited and non-enumerable fields** (src/index.ts:736)
- **Repro (verified by two independent verifiers):** use a class instance with getter `tag`/`on`, or `Object.create({tag:'button', on:{click:'a'}})`, with 20x20 bounds.
  - 0.5.1: legend has `undersized: "20×20 — below 24×24 (WCAG 2.5.8)"` and the SVG has the amber `data-flag="target-size"` bar (846–851 B).
  - HEAD: no undersized entry and no bar (766–769 B).
- **One render now contradicts itself.** The box still gets the bold actionable outline (`hasActEvidence` reads `w`), but it gets no target-size verdict. The exported `targetSizeFinding(record)` still says undersized, so the map and the shared predicate disagree, contrary to issue #4.
- **Why minor:** the format is plain or JSON data, both producers emit plain objects, and the exported predicate itself is unchanged. `bun run stability` misses this because both of its grids use object literals.
- **Fix:** don't rebuild the record. Pass the snapshot dimensions separately, through an internal `sizeFinding(w, width, height, ...)` that both the exported predicate and the renderer call. Or call `targetSizeFinding(w, …)` with a bounds-only override, for example `Object.create(w, { bounds: { value: g, enumerable: true } })`. Note that this override breaks class getters that use private fields. Add class-instance and `Object.create` tests that compare the legend and SVG with `targetSizeFinding(record)`. Add a non-plain row to the stability record-field grid.
- **Re-review scope:** correctness + blast-radius over the fix diff, plus a `bun run stability` re-run.

**M2 [efficiency, CONFIRMED]: the geometry Map lookup inside the O(N²) container scan** (src/index.ts:634, plus 621-623)
- At N=2000, 0.5.1 took about 18–21 ms and HEAD took about 43–51 ms, with byte-identical output. At N=200 the difference is about 0.6 ms vs 0.9 ms, so producer-sized maps of about 145 records lose under 0.3 ms.
- **Fix:** keep a snapshot array parallel to `boxes`, and hoist `const g = geometry.get(w)!` so it is read once per record. Otherwise accept the cost and name it under CHANGELOG `### Measured`, then track the fix with #2829.
- **Re-review scope:** correctness + efficiency over the fix diff, plus stability and this benchmark.

**M3 [correctness, unverified]: the `esc()` non-string guard has no regression test** (src/index.ts:420)
- Restoring 0.5.1's `esc` still leaves the whole suite passing, because every current call site passes a string. The CHANGELOG lists it as a Security fix.
- **Fix:** add a direct test, for example by exporting `esc` for tests. Or reword the CHANGELOG to call it defence-in-depth with no reachable path. Tier 0 only.

**M4 [security, unverified]: "Bounds are read once" overstates the fix for a record that appears twice in `wiring`** (src/index.ts:533)
- `geometry.set(w, g)` runs once per occurrence. A getter that changes between reads lets the second (filtered) read overwrite the geometry drawn for the first occurrence. The lens observed a negative viewBox and rect dimensions. Only finite numbers are stored, so this is not an injection.
- **Fix:** set the snapshot only on first sight (`if (!geometry.has(w))`), and add a duplicate-record test to the #2753 block. Or list the caveat under "Not fixed in this release".
