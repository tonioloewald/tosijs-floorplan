## Blockers (verified majors, must be fixed before tagging)

### B1. #2753 doesn't close its class: `image` is read again between its check and its print. Lenses: security and correctness (merged), verified.
`src/index.ts:713-714` reads `w.image` twice for `typeof === 'string' && w.image.startsWith('data:')`. Line 767 then prints `esc(w.image as string)`, which is a third read. A getter that returns `data:` while the check runs and `https://evil.example/beacon.png` afterwards ends up in `<image href>`. Both verifiers reproduced it: the URL leaked at flip reads k=3–4 on a button and at k≥6 on an img. That breaks the data:-only gate and makes the SVG fetch a remote URL when it is inlined or rasterized. If the late read returns a non-string instead, render throws and the whole map is denied (the #2748 class). This contradicts the README ("each value is read once, so getters and proxies can't change it between check and print") and the CHANGELOG's "Each guarded value is read once".
**Fix:** read it once with `const image = w.image` next to `secret`, run both checks on that local, and print `esc(image)`. Fix the same check-then-reread pattern at `flag.kind` (line 791, and also `targetSizeFinding` at :375) and at `first.label` (lines 797/807). Add `image`, `flag.kind` and `flag.label` to the turncoat tests (see F1).

### B2. #2748 doesn't close its class: wrong-typed fields can still deny the whole map. Lenses: correctness and security (merged), verified.
Every case below makes `schematicSVG` throw and takes the valid records in the same wiring down with it. All were reproduced at HEAD.
- `{tag:'input', label: Symbol(), value:'v'}` throws "Cannot convert a symbol to a string" (the `${w.label}: ${value}` template, around line 670).
- `{tag: Symbol(), secret: true}` and `{tag: Symbol()}` throw at the `<${w.tag}>` templates (around lines 647/656).
- A null-prototype object as `label` or `ref` throws "No default value" from `String(...)`.
- A flag `kind` or `label` getter that turns into a non-string throws `toLowerCase` / `replaceAll` / `.length` errors (lines 375, 797-807). These are double reads too.

The fuzz test (`src/schematic.test.ts:1243`) always builds from `base()`, which is a labelled button. The input, secret, tag-fallback, container and toggle branches never see wrong types. The CHANGELOG line "style was the only field that threw, and the test pins the rest" is false.
**Fix:** route every record value that reaches a caption or ref through one coercion that can't throw (string passes through, finite number is stringified, anything else counts as absent). Never call bare `String()` or interpolate record data into a template literal. Snapshot flag `kind`/`label` once in both the draw loop and `targetSizeFinding`. Run the fuzz test over several base shapes: input with value, secret, unlabeled/tag-fallback, toggle, container, flagged and uncramped. Add a null-prototype object to the wrong-type list. Then correct the CHANGELOG sentence, or make it true.

**Root-cause note for the remediator (completeness gap, unverified):** `esc(s: string)` trusts its input's type and calls `s.replaceAll`. A turncoat that returns `{replaceAll: () => '"/><script>…'}` at print time is reported to get raw markup past esc() on `image`, `flag.kind` and `flag.label`. Making esc() type-safe (`typeof s === 'string' ? … : ''`) closes every sink in one place instead of auditing them one by one. This is the structural fix behind B1 and B2. Do it first, then add the per-field snapshots.
