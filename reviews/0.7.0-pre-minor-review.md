## Follow-ups

### Minor

- [ ] **(unverified) The `<T>(text: T): T` signature is wrong for string literal types** (correctness, src/index.ts:262). `neutralizeProvenance('a ⟷ b' as const)` is typed as the literal `'a ⟷ b'` but returns `'a <-> b'`. Producers that pass plain `string` (haltija) are unaffected. Fix with overloads, `(text: string): string; <T>(text: T): T`. This changes the d.ts only, not runtime behavior. Once 0.7.0 is tagged this signature is public API and lands verbatim in tosijs's vendored file, so it is cheapest to fix **before** the tag if the owner agrees. Otherwise file it.
- [ ] **(unverified) Producer migration is untracked for tosijs** (blast-radius, CHANGELOG.md:13). tosijs `describe()` keeps its own `stripArrows` (../tosijs/src/agent.ts:2308). The claim "a new token reaches every producer at once" does not hold until both producers import the export. File upstream (see below). Optionally soften the CHANGELOG/README wording to "on their next update".

### Nit

- [ ] **Neutralize data before appending the binding arrow** (docs + correctness, llms.txt:37, README ~120, JSDoc; *verified as plausible, adjusted to nit*). Running `neutralizeProvenance` on a finished bound value (`'ada ⟷ a.nick'`) erases the real binding, and `isInteractive` and the ↔ badge are lost. This fails safe and no current producer hits it. Say it explicitly, with an example such as `` `${neutralizeProvenance(pageText)} ⟷ ${path}` ``, and add a test: neutralize, compose, `isInteractive` is still true. The correctness lens and the docs lens reported the same issue; their findings are merged here.
- [ ] **(unverified) Two hard-coded token lists** (correctness, docs and blast-radius lenses, merged; src/index.ts:243/247). `PROVENANCE_TOKENS` and `neutralizeArrows`' `replaceAll` chain (plus the parse sites at ~236/271/316) are maintained separately. The test pins only the set equality with the two constants. Fix: derive both from one token→replacement table, or add a test that `neutralizeProvenance(PROVENANCE_TOKENS.join(''))` contains no token. Emitted bytes do not change.
- [ ] **(unverified) README line ~123 is not re-wrapped** (docs). Re-flow the paragraph. Its "(0.7.0, #3387)" reference becomes correct once the tag exists.
